# 桌面版目标用户试用指南

这一版优先验证实习、校招场景的「岗位—材料—面试—训练」流程。移动端、语音、代码执行与 Offer 对比不在本轮范围。

## 准备

按 README 启动前后端并填写模型配置。本机单人使用，每位试用者使用自己的数据目录和模型配置。不要把没有账号隔离的本地服务直接作为多人公共服务。

开始前说明：记录保存在本机；解析、生成、分析和评分会调用配置的模型服务。扫描件会发送页面图像。可以使用去掉联系方式的材料；也可先用明确标注为测试的虚拟材料熟悉流程。

## 一次约 30 分钟的试用

请试用者自行操作，观察者记录卡点，不逐步指挥。

1. **保存一个真实岗位。** 填写公司、岗位、城市、批次及 JD；写下下一步和日期。检查是否能从首页找到它，刷新后是否还在。
2. **整理一段经历。** 先保存草稿，再补全个人贡献和实际结果，核对来源后确认。观察是否理解草稿与用户确认的区别；不要要求为了好看而补写没有依据的数字。
3. **按岗位准备简历。** 上传正在使用的简历，检查解析内容、修正一处问题，生成岗位版本。接受、编辑或恢复部分内容，保存新版本；比较版本并检查 DOCX 或打印预览。遇到导出暂停时，观察能否理解原因并解决。
4. **做一次针对岗位的面试。** 选择岗位与简历版本，检查问题是否涉及实际 JD 或项目。可选训练模式或结束后集中反馈的模拟模式。刷新页面后继续；结束后从一个弱点创建专项训练。
5. **做两次同题练习。** 阅读固定标准，作答后检查引文是否确实来自自己的回答。根据建议修改，再次提交，比较具体条目变化；观察是否把练习分数误解为录用概率。
6. **记录一次真实面试。** 若已有真实经历，分别填写问题、当时的回答、明确反馈和个人推测，检查能否找到后续准备入口。

## 记录表

| 项目 | 记录内容 |
| --- | --- |
| 求职阶段 | 实习 / 应届校招；目标岗位大类，无需姓名和联系方式 |
| 完成情况 | 每项独立完成、需要提示、无法完成 |
| 准备耗时 | 从保存岗位到得到可使用简历/训练题的耗时；单独记录模型等待 |
| 事实纠错 | 哪句话有问题、原材料依据、用户如何纠正 |
| 采纳情况 | 哪些建议有用、哪些空泛、哪些被拒绝以及原因 |
| 操作卡点 | 所在页面、刚做了什么、实际结果；经本人同意后记录截图 |
| 两次练习 | 标准是否一致、引文是否真实、哪些条目有可解释的变化 |
| 整体评价 | 最愿意继续使用的一项；最希望解决的一个问题 |

最后询问：「你是否愿意在下一次真实投递时再打开它？当时你最希望它帮你完成哪件事？」

首轮可邀请 5–10 位目标用户。优先修复事实错误、无法完成的任务、材料丢失和不明确的操作反馈。真实面邀率按岗位和渠道持续观察，不能由小样本直接归因于产品。

## 数据结束处理

试用者可在「我的档案 → 数据与模型使用」导出结构化记录，或输入 DELETE 清空本地工作区。JSON 不含上传文件二进制、长期记忆或面试恢复文件，也不是恢复包。清空不影响模型服务商已经持有的数据。模型任务运行时需先等待完成。

如果使用旧版，Mem0 曾默认把历史写在工作区外的共享历史库；新版不会自动删除该共享库，以免影响其他应用。新版新增历史位于 DATA_DIR/memory_history.db。
